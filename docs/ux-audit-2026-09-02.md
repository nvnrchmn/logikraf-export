# Audit UI/UX — export.logikraf.id

- **Tanggal:** 2026-09-02
- **Metode:** inspeksi kode (frontend React + backend), penelusuran alur nyata hari ini (order → dokumen → payment → shipment), belum tes perangkat fisik.
- **Cakupan:** seluruh halaman (Login, Dashboard, Orders, OrderDetail, Products, Buyers, Users, Audit, Settings, Calculator, Guide) + dokumen PDF + API.
- **Skor:** 1 (buruk) – 5 (baik).

---

## A. 10 Prinsip Heuristik Nielsen

### 1. Visibility of System Status — 3/5
Sudah: skeleton loading, banner error inline, badge status, breadcrumbs.
Kurang:
- Tidak ada umpan balik sukses eksplisit pada mayoritas aksi → **sudah diatasi dengan sistem toast** (OrderDetail, Products, Buyers; masih bisa diperluas ke Users/Dashboard).
- Saat tombol ditekan, `busy` global menonaktifkan banyak tombol tapi tidak semua tombol menunjukkan spinner sendiri.
- Aksi blur (catatan pembayaran auto-save) tidak memberi tahu pengguna bahwa tersimpan.

### 2. Match Between System & Real World — 4/5
Bahasa Indonesia untuk UI internal, Inggris untuk dokumen ekspor — konsisten per konteks. Istilah domain akurat (HS Code, Incoterm, NIB/NPWP, LCL/FCL, PEB).
Kurang: singkatan (SKU, AWB, CBM) tanpa keterangan di beberapa tempat; saran: tooltip/`hint` (beberapa form sudah punya).

### 3. User Control & Freedom — 3/5
Sudah: modal bisa ditutup via X/backdrop, pembatalan order ada, hapus item/dokumen ada konfirmasi.
Kurang:
- Konfirmasi hapus masih `window.confirm()` native (Produk, Buyer, item) → tidak seragam, tidak bisa di-center/styled → **ganti dengan ConfirmDialog custom**.
- Tidak ada undo untuk hapus master data (produk/buyer). Saran: soft-delete / toggle `active` (kolom sudah ada) + pemulihan.

### 4. Consistency & Standards — 4/5
Satu design system (kartu `rounded-xl`, tombol, ikon lucide, tema zinc/indigo) konsisten. Ketidakkonsistenan utama: `confirm()` native vs modal custom; teks tombol belum seragam di semua tempat ("Simpan" vs "Buat dokumen" vs ikon saja); indikator warna status tidak dipakai seragam (hijau = sukses vs status "draft" abu).

### 5. Error Prevention — 3/5
Sudah: validasi level di server dengan pesan 400 jelas; input qty numerik; alur status memakai state machine (tidak bisa lompat status); PEBRequired otomatis menghindari salah tafsir regulasi.
Kurang: validasi client-side minim (format HS code, isi wajib sebelum submit menunggu error server), tidak ada konfirmasi saat mengubah data order yang sudah punya dokumen terbit (saran: info "dokumen perlu regenerate — nomor tetap").

### 6. Recognition Rather Than Recall — 4/5
Dropdown produk/buyer + pencarian, breadcrumbs, ikon bermakna, nilai total terhitung otomatis.
Kurang: input ulang data berulang (mis. price saat menambah item); saran: default harga produk terisi otomatis saat pilih produk (sudah lazim, kecil).

### 7. Flexibility & Efficiency — 4/5
Role admin/ops, halaman Guide, fitur **Data Kirim Kurir** (copy-paste pack) = contoh efisiensi bagus.
Kurang: belum ada duplikasi order cepat ("salin jadi order baru"), default field (shipping mode/incoterm yang sering sama).

### 8. Aesthetic & Minimalist Design — 4/5
Mobile-first dark theme rapi, hierarki jelas, animasi halus.
Kurang: **OrderDetail sangat panjang** (header, item, pengiriman, pembayaran, data kurir, dokumen) → saran: section `details`/collapse atau tab, ringkasan utama di atas.

### 9. Help Users Recognize, Diagnose, Recover from Errors — 3/5
Pesan error merah inline ada, tetapi sebagian generik ("gagal menyimpan") tanpa sebab/aksi lanjut. Toast sukses baru ada.
Saran: petakan pesan error API → bahasa manusia + langkah perbaikan (mis. "payload tidak valid" → "Lengkapi field wajib: alamat buyer").

### 10. Help & Documentation — 4/5
Halaman Guide kuat (3 moda, aturan PEB berbasis berat, istilah, larangan pecah kiriman).
Saran: tautan Guide dari OrderDetail ("bantuan") + tooltip istilah di form.

**Rata-rata Nielsen: ~3,7/5** — fondasi baik, prioritas: feedback konsisten + konfirmasi custom + OrderDetail yang lebih terstruktur.

## B. Prinsip Psikologi UX

| Prinsip | Status | Catatan |
|---|---|---|
| **Hick's Law** | 3/5 | Aksi per kartu sudah dibatasi; OrderDetail terlalu banyak tombol sekaligus → kelompokkan per section |
| **Jakob's Law** | 4/5 | Layout dashboard/status mengikuti pola familiar; jaga konsistensi ikon |
| **Gestalt (proximity/grouping)** | 4/5 | Kartu & spacing baik; beberapa form panjang tanpa grouping visual (bisa pakai fieldset/divider) |
| **Zeigarnik / progress** | 3/5 | Status order berurutan jelas; tambahkan visual progress step (draft→…→completed) untuk memicu penyelesaian |
| **Loss aversion** | 3/5 | Hapus permanen: dokumen sudah modal + konsekuensi; produk/buyer masih `confirm()` polos → custom dialog + teks konsekuensi |
| **Peak-end rule** | 4/5 | Toast sukses di akhir aksi meningkatkan memori pengalaman (baru ditambahkan) |
| **Aesthetic-usability** | 4/5 | Dark theme konsisten; awasi teks 11px (kontras kecil) pada info penting |

## C. Temuan Khusus per Halaman

- **OrderDetail** — paling padat; section tanpa collapse; harga per item tanpa indikator mata uang eksplisit di beberapa tempat; catatan kecil "regenerate = nomor tetap" akan menenangkan pengguna.
- **Products / Buyers** — hapus pakai `confirm()` native; form modal sudah bagus (Field+hint), tambah validasi HS code; modal kini center + scroll-lock.
- **Users / Audit** — halaman admin; audit butuh filter (tanggal/aksi/user); nonaktifkan user (active flag) lebih baik daripada hapus.
- **Settings** — feedback inline "tersimpan ✓" bagus; preview tanda tangan ada.
- **Dashboard** — belum diaudit detail; saran: angka periode berjalan + daftar order perlu aksi (mis. menunggu DP/kirim).
- **Guide** — kekuatan utama; bisa ditambah pencarian istilah.
- **Modal** — UI.Modal kini center (dvh + my-auto + scroll internal + scroll-lock body); sama untuk modal hapus dokumen.
- **Toast** — gaya SweetAlert (dialog tengah, ikon, auto-dismiss 2,6 dtk, tombol tutup) — terpasang di OrderDetail/Products/Buyers.
